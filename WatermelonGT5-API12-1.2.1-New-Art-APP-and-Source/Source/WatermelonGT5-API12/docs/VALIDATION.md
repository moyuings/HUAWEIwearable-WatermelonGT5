# 1.2.1 验证记录

目标：GT5，466×466圆屏，Lite Wearable API12。用户报告应用预算512KB、整机32MB；此前固件6.0.0.32，本轮实际固件、运行时API与图片池未知。hdc本轮返回[Empty]，没有GT5真机验证。

## 本轮修改

11张用户提供素材从512母图重新处理，清除番茄、桃子、菠萝、椰子旁的邻图残片，居中、缩放至18～116像素；同步替换114/80启动图标。旧第三方图像和原图备份不在当前交付中。新代码许可按用户最后要求为MIT，图片单独CC BY-NC 4.0。

保留1.2.0的物理、合并、计分、40颗上限、30/60目标模式、固定物理步长、有限补步、输入、保存、后台暂停和性能/日志诊断。源码哈希对照检查这些逻辑文件未改。

## 验证分层

- 素材检查：见 assets.json、artwork-preview.png；文件尺寸、透明背景、圆形边界、原始来源SHA、派生SHA、旧素材排除由电脑检查。母图不放在运行资源目录。
- 代码测试：tools/verify.cjs 执行真实生产模块，覆盖碰撞、合并、帧率切换、存储失败、后台/退出及性能诊断。结果见 code-tests.json / code-tests.log；不是真机测试。
- 官方构建与包检查：见 build-1.2.1.log、package-verification.json；独立SDK JerryScript快照比对、API12配置、default入口、13张图片及双图标均检查。未配置签名是预期状态。
- SDK原生预览：见 preview/下当前版本各场景JSON、截图与日志。配置512KB堆、466圆屏；传输图片数量不是实际显示FPS，测试替身不进入生产工程。
- GT5真机：未连接。新图片显示、重复换图的图片池占用、实际渲染帧率、安装和签名、后台返回及持久化仍待目标设备复测。

## 性能与内存范围

本轮没有修改帧率优化逻辑，不能声称解决此前GT5在60模式约11Hz的问题。图片改变不保证提升FPS。30/60仍为目标更新模式，不是GT5已稳定达到的呈现速度。

11张水果单份RGBA估算合计197696字节，114/80图标合计77584字节；尺寸保持不变，所以这部分理论解码总量未因换图增加。若40个最大水果均独立解码，单水果层可达2152960字节，原生是否共享仍未测；图片池与512KB JS堆分别评估。压缩体积与运行内存不能等同。

## 最少GT5复测

1. 安装本版1.2.1，确认新图标与水果；30模式点击/滑动投放，观察合并、失败线与暂停。
2. 切到60模式并保留局面，约10颗水果时暂停记录循环/数据/物理峰值；实际显示帧率仍需可靠帧计数或外部拍摄。
3. 后台返回、重开、退出重进检查最高分与帧率设置；异常时导出本应用日志二维码。
